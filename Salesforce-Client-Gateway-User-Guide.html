1. Introduction

Cedar Gate internal Salesforce Service Console and Client Gateway portal — cases, vendors, accounts, and Jira integration.

What is the Client Gateway?

The Cedar Gate Client Gateway (clientgateway.cgt.us) is the client-facing portal built on Salesforce Experience Cloud. It replaces the legacy Cedar Gate Customer Community and provides a standardized support experience across Cedar Gate products.

Clients use the Client Gateway to:

  • Submit and track support cases
  • Onboard new groups and manage vendor data feeds
  • Access training materials and knowledge articles
  • Run organization-level case reports
  • Update contact information

Cedar Gate staff use the internal Salesforce Service Console (https://cedargate.lightning.force.com/lightning/page/home) to manage cases, vendors, accounts, and integrations with Jira.

4. Support Cases — General Workflow

4.1 Create a New Support Case

  1. Tap Support in the navigation bar
  2. Tap Create New Case
  3. Select a Request Type (see Section 7 for specialized types)
  4. Tap Next
  5. Complete required fields:

- Product Name

- Priority

- Version (if applicable)

- System Environment

- Subject / Title

- Description (detailed problem description)

  1. Upload supporting files or screenshots if available
  2. Tap Submit

A Case Number is assigned upon submission for tracking.

4.2 View Current and Past Cases

  1. Tap Support to view the case list
  2. Select a case to open the record
  3. Filter views:

- My Cases — cases where you are the assigned contact

- My Organization's Cases — all open and closed cases for your organization

- My Organization's Open Cases — open cases only

4.3 Case Detail Tabs

Each case record contains three tabs:

TabContents
Feed (default)Posts, email updates, and comments
DetailsCase fields, customer information, vendor details, entitlements
RelatedEmails, case history, comments, related cases, attachments, vendor relationships

4.4 Update a Case

Clients cannot directly change case status or priority. To request a change:

  1. Open the case from Support
  2. Post a comment in the Feed describing the requested change
  3. The assigned Support Analyst is notified automatically

To add information or attachments:

  1. Open the case
  2. Post an update in the Feed or attach files
  3. Email replies to case notification emails are synced to the Feed automatically

4.5 Case Detail Fields (Internal View)

When viewing a case in Salesforce (internal), the Details tab includes:

Case Information

  • Case Owner, Status, Case Number, Priority
  • Case Origin (default: Web), Request Type, Product, Internal Project
  • Case Reason / Work Type (mandatory field)

Customer Information

  • Contact Name, Contact Phone, Account Name, Contact Email
  • Account Manager, CS Delivery

Description Information

  • Subject, Description, Root Cause, Internal Ticket Number

Vendor Details (NGO/VCR cases)

  • Group Name, Eligibility Vendor, Historical Data Range
  • Controls Total Received, Implemented Status

Entitlement / SLA

  • First Response, Workaround Provided, Time Tracking
  • Root Cause SLA Timestamp, Hotfix Request, Internal Ticket Created Timestamp

System Information

  • Case Record Type, Date/Time Opened, Date/Time Closed

6. File Attachments and Protected Health Information

Uploading Files

Screenshots and supporting documentation can be attached to cases from the Feed or Related tab.

PHI Requirements

Protected Health Information (PHI) must be password protected before upload.

  • Your Cedar Gate Client Success Manager provides a unique password for all sensitive documents
  • Documents containing PHI that are not password protected will be deleted and must be re-uploaded with protection
  • Cedar Gate recommends password-protected Microsoft Word or Excel documents

Creating Password-Protected Files

Microsoft Word (Windows)

  1. Open the document in Word
  2. Select File → Info → Protect Document
  3. Enter the password provided by Cedar Gate
  4. Confirm the password

Microsoft Excel (Windows)

  1. Open the workbook in Excel
  2. Select File → Info → Protect Workbook
  3. Enter the password provided by Cedar Gate
  4. Confirm the password

MacOS and other version instructions:

  • Word: https://tinyurl.com/mtt5ecdb
  • Excel: https://tinyurl.com/4k7bhxmu

Attachment Sync Limits

  • Attachments up to 9 MB sync between Salesforce and Jira
  • Attachments larger than 9 MB are not supported for sync
  • File names containing " H" (space + H) may fail to sync

7.2 New Group Onboarding (NGO)

When to use: A new population (group) does not exist in the client's Cedar Gate application.

Steps:

  1. Click Support from the Client Gateway dashboard
  2. Select New Group Onboarding as Request Type
  3. Click Next and complete all mandatory fields
  4. Click Create
  5. On the Case screen:

- Click Upload Files for attachments (e.g., crosswalk files)

- Click New in Data Feeds to add vendor contacts and details

Data Feeds: Vendor contacts and names cannot be entered directly in the Vendor Details section. Use the Data Feeds popup; entries sync to Vendor Details and internal tickets.

Multiple historical vendors: Create a separate Data Feed for each vendor with appropriate date ranges.

Example — Multiple vendors:

Cigna – Eligibility, Medical: 1/1/2017 – 12/31/2019 (Historical)
Anthem – Eligibility, Medical: 1/1/2020 – 12/31/2021 (Historical)
UHC – Eligibility, Medical: 1/1/2022 – ongoing (Ongoing)

NGO workflow after submission:

  1. Case assigned to Account Vendor Manager (or VM Queue if no VM designated)
  2. VM team creates Vendor Relationship (VR), Vendor Files, and IFR tickets
  3. Client sends introduction email to DW_vendor_notification@cedargate.com (unless VM has prior relationship with vendor)
  4. VM team shares weekly Vendor Status Report with Client Success Manager
  5. Status changes to In Progress when VM begins vendor outreach
  6. Data team loads group after file validation; status moves to Client Acceptance

7.3 Client Control Total (CCT)

Cedar Gate requires a Control Total for all NGO cases.

  1. Select Client Control Total as Request Type
  2. Click Next, complete mandatory fields, click Create
  3. Upload the control total document as an attachment
  4. View attachments via View All in the Attachments section

7.4 Account Structure Digest (ASD)

For eligibility data feeds, Cedar Gate may produce an Account Structure Digest case for client review.

  1. Go to My Cases and locate the Account Structure Digest case
  2. Open the case and review attached documents (Division Type, Plan Type, Employee Status Benefits)
  3. Provide feedback or approval via a comment in the Post section

7.5 Vendor Change Request (VCR)

When to use: Vendor changed for an existing group, or adding a new data feed for an existing group.

  1. Click Support from the dashboard
  2. Select Vendor Change Request as Request Type
  3. Click Next, complete mandatory fields including Expected Run Out Period from the previous vendor
  4. Upload attachments and add Data Feeds (same process as NGO)
  5. Case appears under My Cases

7.6 Group Termination Request (GTR)

  1. Create a new case with Request Type Group Termination Request
  2. Complete required fields: Subject, Description, Priority, Account Name, Group Name, Products, Termination Date
  3. Submit the case

When the case status is set to Closed, the linked Jira ticket is updated to Closed.

11.8 Vendor Relationship

Vendor Relationships link a vendor to a specific client account and group. They are the foundation for NGO/VCR onboarding.

  • Created from the vendor page (Create Vendor Relationship), Case Related tab, or Vendor object
  • Contains VM Case ID field linking to the NGO/VCR case and its Jira ticket
  • Contains Legal Agreements section (see Section 16)
  • Vendor contacts managed through Vendor Relationship records (up to four per VR)

See Section 11.10 — Vendor Relationships Page for the full record layout and field reference.

11.9 Vendor Files and IFR

When VM team receives an NGO/VCR case, Vendor Files are created under the Vendor Relationship. Each Vendor File represents a single data feed (by file type and date interval) and can generate an IFR (Implementation File Receipt) ticket in Jira.

  • IFR tickets are not auto-created when a Vendor File is saved — use the Create Jira button on the record page
  • Salesforce automation handles IFR creation via the Create Jira button and the Jira API
  • See Section 11.10 — Vendor Relationships Page for Create Vendor File workflow
  • See Section 11.11 — Vendor File Page for the full record layout and field reference
  • See Section 14 — IFR Integration for the complete Jira field mapping table

11.10.6 VM Case ID and NGO/VCR Linkage

The VM Case ID field links the VR to the originating NGO or VCR support case and drives IFR parent-ticket auto-linking.

FieldBehavior
VM Case IDLookup to Case records; accepts Case Number; only New Group Onboarding and Vendor Change Request request types appear in lookup
New Group Onboarding ticketRead-only field (non-System Admin); populated from the linked NGO case Jira ticket

VM Case ID lookup rules:

  • Only cases with Request Type = New Group Onboarding or Vendor Change Request are searchable
  • Cases with no Request Type set do not appear in the lookup
  • Freshly created NGO/VCR cases are immediately available in the lookup
  • VR name format must follow {Acronym}-{Vendor}-{Group} for standard validation

IFR parent-ticket auto-linking (via VM Case ID):

VM Case ID StateIFR Parent Ticket Behavior
BlankIFR created with no parent ticket
VCR case (no NGO Jira)IFR created with VCR as parent
NGO case with Jira ticketIFR auto-linked as child of NGO Jira ticket
Linked NGO/VCR Jira closedCreate Jira blocked with message: *"The NGO/VCR ticket associated with this vendor file is closed in Jira"*

Log a Call sync: When a call is logged from the VR Activity sidebar, the activity appears on the case referenced in VM Case ID and on the associated Jira ticket (when present). The New Group Onboarding ticket and VM Case ID should reference different cases when both are populated.

11.10.7 Legal Agreements Section

The Legal Agreements related list on the VR record manages NDA and data agreements tied to this vendor–account–group combination.

  1. Scroll to the Legal Agreements section on the VR Details tab (or open from the Related list)
  2. Click New to create a Legal Agreement
  3. Complete fields: Legal Type, Initial Date, Complete Date, Signature Required, Signature Received
  4. Name format: {Client Acronym}-{Vendor}-{Group}-Legal Agreement
  5. Click Create Ticket on the Legal Agreement to generate a LEG project Jira ticket

Legal Agreement fields sync bidirectionally with Jira (see Section 16). The Legal Agreements value on the VR also syncs to IFR Jira tickets created from Vendor Files under this VR.

11.10.8 Create Vendor File Workflow

The Create Vendor File button generates Vendor File records from the VR's multi-select fields.

Prerequisites:

FieldRequirement
Group Name(s)At least one group selected (mandatory)
File TypeAt least one file type selected (multi-select picklist)
Date IntervalAt least one interval selected (Historical / Ongoing multi-select)

Workflow:

  1. Open the Vendor Relationship record
  2. Ensure Group Name(s), File Type, and Date Interval are populated and saved
  3. Click Create Vendor File
  4. Salesforce generates one Vendor File per combination of Group × File Type × Date Interval
  5. Each Vendor File auto-populates: Vendor File Name, File Type, File Status, Date Interval, Frequency, Jira Ticket Type (Implementation File Receipt), and Vendor Relationship link

Vendor File Name format: {Account Acronym}-{Vendor}-{Group}-{File Type}-{Date Interval}

Frequency defaults:

11.11.6 File Status Lifecycle

File Status (Overall_Status__c in Salesforce) tracks the vendor file through receipt and implementation. It syncs bidirectionally with the Jira IFR File Status field.

StatusMeaning
WaitingDefault on IFR creation; awaiting file delivery from vendor
ReceivedFile has been received from the vendor
RejectedFile was rejected (quality, format, or content issues)
Ready to ImplementFile validated and ready for data team implementation
Data IncompleteFile received but data is incomplete
Layout OnlyLayout received; full data file pending
File Cancelled By ClientClient cancelled this feed; status preserved even if Jira IFR is closed

Status transition notes:

  • When an IFR Jira ticket is Closed, Salesforce File Status updates to Received (unless status is File Cancelled By Client)
  • File Received Date cannot be a future date (validation error: *"Future Date not allowed"*)
  • File Status and Overall Status must have matching values

11.11.7 Relationship to Vendor Relationship and NGO/VCR Cases

Vendor Files sit in the middle of the NGO/VCR onboarding hierarchy:

NGO/VCR Case → Vendor Relationship (VM Case ID) → Vendor File(s) → IFR Jira Ticket(s)
ObjectRole
NGO/VCR CaseClient-submitted onboarding or vendor change request; drives VM workflow
Vendor RelationshipLinks vendor + account + group; holds VM Case ID, Legal Agreements, SFTP User ID, vendor contacts
Vendor FileOne record per file type + date interval; tracks file receipt and IFR status
IFR Jira TicketData team work item for receiving, validating, and implementing the vendor file

Workflow:

  1. Client submits NGO or VCR case with Data Feeds
  2. VM team creates Vendor Relationship(s) from the case Related tab
  3. VM team creates Vendor File(s) from the VR (Create Vendor File) — one per file type / date interval / group combination
  4. VM team clicks Create Jira on each Vendor File to generate IFR tickets
  5. IFR tickets auto-link to the NGO (or VCR) parent ticket when VM Case ID conditions are met
  6. Data team updates File Status as files are received and implemented
  7. NGO/VCR case fields (Core Feeds Received Date, Feeds Ready to Implement Date, Work Type) roll up from linked IFR tickets

Vendor Files are deleted when their parent Vendor Relationship is deleted.

18. Frequently Asked Questions

A: Your Client Success Lead will communicate your migration date with ample notice.

A: A step-by-step user guide and webinar are provided before migration.
