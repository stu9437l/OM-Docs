# OM Flow Diagram

A self-contained single-page app. No build step, no dependencies.

## Run

Open `flow/index.html` directly in a browser, or serve the folder:

```bash
python3 -m http.server 8788 --directory flow
# then open http://localhost:8788/
```

## Files

| File | Purpose |
| --- | --- |
| `index.html` | Page shell: masthead, module tabs, diagram stage, Lambda panel, user-guide panel, legend, controls |
| `styles.css` | Dark palette (`#0f172a` background, `#1e293b` cards, `#f8fafc` text), node kinds, pulse keyframes |
| `flows.js` | All flow data: `MODULES` → `views` (sub-tabs) → `nodes`, `layout` (grid column/row), `edges` |
| `lambdas.js` | Per-module AWS Lambda flows scanned from local OM repos (`LAMBDA_FLOWS`) |
| `guide.js` | Per-module Confluence user-guide text (`GUIDES`). Regenerated by `scripts/build-guides.py` |
| `app.js` | Rendering, SVG connectors, animation, click-to-expand, Play/Pause/Reset, Lambda + user-guide panels |

The top tab bar selects a module. Modules with more than one view show a second
sub-tab bar; a single-view module hides it.

## Interaction

- The animation pulses one step at a time and loops over the active view.
- Clicking a step pauses the loop and expands that card with descriptive text; clicking it again collapses it.
- An expanded card with a `jump` target offers a button straight to the related module and view, which is how the flows connect.
- `Play`/`Pause` toggles the loop; `Reset` returns to step one and resumes.
- Cards are keyboard reachable — `Tab` to a step, then `Enter` or `Space`.

## User guide panel

Each module (and sub-view, where the docs differ) has a **User guide** block under
the diagram. Text is condensed from the Confluence Operations Manager documentation
mirror (`~/.cursor/domain/knowledge-base/operations-manager`) plus the QC navigation
walk where a Confluence parent page has no body (Processing Dashboard).

Regenerate after editing `scripts/build-guides.py`:

```bash
python3 scripts/build-guides.py
```

## Adding or editing a step

Edit `flows.js` only. Add the node to the view's `nodes`, give it a `[column, row]`
entry in `layout`, and add its `edges`.

- `kind` drives the accent colour: `start`, `action`, `system`, `decision`, `exception`, `exit`.
- `jump` cross-links to another view as `"moduleId"` or `"moduleId:viewId"`.
- `flag: "unverified"` marks a label or behaviour not confirmed in the documentation.

Every `start` node is treated as a valid entry point, so a view can legitimately
have more than one (for example calendar-created tickets, or the Latest Ticket
Status panel).

## Content notes

Content is drawn from the OM Confluence documentation, the QC navigation walk, and
the current front-end navigation. All account, ticket, and file identifiers shown
are placeholders — no PHI or financial identifiers are embedded.

The **Lambda flow** panel under each module is built from a scan of local OM repos
(`repo_om_patches`, `repo_om_processingcalendar`, `repo_om_frontv2`, and related).
Modules without a matching Lambda package show an empty-state note.
